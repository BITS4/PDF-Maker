# Quality policy

## Blocking verification

`./gradlew verify` is the canonical local gate. CI invokes its constituent tasks independently so failures are easy to
locate, and the release workflow repeats the release-relevant checks from a clean runner.

| Signal               | Blocking task                              | Policy                                                                  |
| -------------------- | ------------------------------------------ | ----------------------------------------------------------------------- |
| File size            | `checkSourceFileSize`                      | Every production Kotlin file is at most 500 physical lines.             |
| Logging boundary     | `checkPrivacySafeLogging`                  | Only the redacting Timber sink may call Android's raw logging API.      |
| Formatting           | `ktlintCheck`, `:app:ktlintCheck`          | Every Kotlin source and build script follows the enforced style.        |
| Static analysis      | `:app:detekt`                              | Every Detekt finding fails; no generated baseline is accepted.          |
| Android analysis     | `:app:lintDebug`                           | Every Android lint warning and error fails the build.                   |
| Unit behavior        | `:app:testDebugUnitTest`                   | Every JVM unit test must pass.                                          |
| Global coverage      | `:app:koverXmlReportDebug`                 | The complete, unfiltered app remains visible in XML and HTML reports.   |
| Critical coverage    | `:app:koverVerifyCritical`                 | At least 90% line and 75% branch coverage in the named critical domain. |
| Compilation          | `:app:compileDebugKotlin`                  | Kotlin production sources compile on JDK 17.                            |
| Packaging            | `:app:assembleDebug`, `:app:bundleRelease` | The debug APK and minified release bundle compile.                      |
| Device behavior      | `:app:connectedDebugAndroidTest`           | Security/platform contracts pass on the CI API 35 emulator.             |
| Runtime dependencies | `writeRuntimeOsvManifest` + OSV Scanner    | The locked release graph contains no known vulnerability.               |

At the verified 2026-09-03 source freeze, the repository contains 219 main-source Kotlin files and one debug-only test
helper, 79 JVM test files with 505 executed tests, and 13 connected-test files with 47 declared test cases. That is one
test file for every 2.39 production/helper files; coverage counters are regenerated by the final clean verification
run rather than copied from an earlier report.

## Coverage scopes

The debug report intentionally includes the entire application, including Compose UI and Android adapters. Keeping
that scope visible prevents a filtered report from being presented as whole-application coverage. It is a transparent
measurement rather than a weak pass/fail floor; new tests should continually move it upward.

The clean source-freeze run produced these exact Kover counters:

| Scope                   | Lines                | Branches            | Methods           | Instructions           | Classes          |
| ----------------------- | -------------------- | ------------------- | ----------------- | ---------------------- | ---------------- |
| Whole debug application | 3,805/18,604, 20.45% | 2,599/9,202, 28.24% | 740/2,413, 30.67% | 25,846/170,420, 15.17% | 206/642, 32.09%  |
| Tested critical domain  | 3,196/3,473, 92.02%  | 2,441/3,178, 76.81% | 578/617, 93.68%   | 21,866/24,030, 90.99%  | 107/107, 100.00% |

The `critical` Kover variant is an additional gate, not a replacement report. It is copied from the `debug` variant so
both scopes execute the same complete JVM suite, then selects the explicitly named, directly tested classes in
`app/build.gradle.kts`. Those classes enforce bounded import ownership, safe naming/output, document inspection,
encryption and PIN policy, page/range and workflow-state policy, render sizing, hardened office-package XML, image
export, OCR text formatting, sharing, and extracted viewer/editor behavior. Its 90% line and 75% branch gates provide
meaningful regression protection without claiming that UI code has the same coverage. The test task and critical
aggregation tasks deliberately bypass Gradle's build cache and up-to-date shortcut so a prior focused test run cannot
leave partial execution data behind. The measured report values are regenerated before each release.

Generate both inspectable reports with:

```bash
./gradlew :app:koverXmlReportDebug :app:koverHtmlReportDebug
./gradlew :app:koverXmlReportCritical :app:koverHtmlReportCritical
```

## No-baseline policy

Ktlint, Detekt, and Android lint use no baseline: every finding is blocking. Fix or refactor a reported defect instead
of hiding it in generated suppression state. A narrowly scoped source suppression is acceptable only when the rule is
provably inapplicable, and its review must include the rationale and focused behavior tests.

Coverage thresholds follow the same ratchet: measure the committed reports, add tests, and raise a floor in the same
focused change. Never reduce a floor or narrow the critical class list merely to pass CI.
